Every time you [publish](/workflows/publish-and-enable/) a workflow, Kanri creates a numbered, permanent **version** (v1, v2, v3, etc.). Version history lets you see exactly what each version contained, when it was published, and which runs used it.

---

## Viewing the version list

1. Open any workflow in the editor.
2. Click **Versions** in the toolbar.
3. A list of versions appears, newest first, including any saved draft.

Each entry shows:
- The version number (v1, v2, v3…)
- When it was published
- Whether it's the current active version

---

## Viewing a specific version

Select **View canvas** beside a published version. The workflow canvas opens in **read-only
mode**, showing the trigger and steps saved in that version.

This is useful for:
- Auditing what the workflow was doing at a specific point in time.
- Understanding why a run behaved a certain way (by checking which version it ran on).
- Comparing the current setup to a previous configuration.

You cannot edit a past version. If you want to revert to an old configuration, you'd need to recreate those settings in a new draft and publish it.

---

## How versioning protects in-progress runs

When you publish a new version of a workflow, **in-progress runs are not affected**. Each run is pinned to the version that was active when the run started.

**Example:** A member is in the middle of a 3-day delay step in v2 of your "Renewal Reminder" workflow. You make changes and publish v3. The member's run stays on v2 — it finishes with the v2 logic. New runs created after the publish use v3.

This means you can safely update a workflow at any time without disrupting members who are mid-run.

Versioning freezes the workflow definition, not every record it uses. Actions can read current
member details and the current content of a selected message template when they execute.
Changing those records can affect a later step even when the run stays on an older workflow
version. Disabling or deleting the workflow cancels in-progress runs.

---

## The current draft

If you're currently editing a workflow, you'll see a **Draft** badge in the version list. The draft is not a published version — it's a work in progress. It won't appear in run history until it's published.

---

## Tracking which version ran

In [Run History](/workflows/run-history/), every run shows which version number it used. This makes it easy to understand any run's behavior — you can click through to view that exact version on the canvas.
